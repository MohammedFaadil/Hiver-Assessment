How this works

  1. Data: ~77k reconstructed first-contact AmazonHelp threads from the Kaggle "Customer Support on Twitter" dataset, filtered to English.
  2. Intent taxonomy: 8 categories derived from reading real threads (see the repo's LABELING_GUIDE.md).
  3. Trivial baseline: majority-class intent, one canned reply, never escalates.
  4. Simple baseline: TF-IDF + Naive Bayes classifier (pure numpy, no scikit-learn) + nearest-neighbor retrieval-templated reply.
  5. Headline system: same retrieval grounding, reply drafted by an LLM (Groq) conditioned on real historical resolutions, with a deterministic, auditable rule engine — not the LLM — deciding escalation.

Escalation policy

A message is routed to a human when: it's in a policy-flagged high-risk intent category (billing, explicit complaints, unclear), the classifier's confidence is low, no sufficiently similar historical resolution was found, or the message contains urgency/frustration/safety language.

See DECISION_LOG.md and REPORT.md in the repo for the full reasoning, baselines comparison, and honest failure analysis.
